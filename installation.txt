How this machine is built from this repository, and how an agent running on
it resets it to that state. Every action is idempotent: run all of them, in
order, for a full reset.

Preconditions:
C:\data\accounts.txt is present.
Display 1920x1080 at 150% scaling.
Windows logs sonta in at boot; Brave is logged in to claude.ai.

Needed Tools, each at its default install path; only install if not present.
  winget install Git.Git
  winget install GitHub.cli
  winget install Brave.Brave
  winget install Notepad++.Notepad++
  winget install UB-Mannheim.TesseractOCR
  JDK 26 at C:\Program Files\Java\jdk-26.0.2, no JAVA_HOME
  git config --global user.name marcoautomation2
  git config --global user.email marcoautomation2@outlook.com
  Eclipse at C:\data\tools\eclipse, for EclipsePlugin work (not installed, just the portable version)

Actions:
  The checkout, cloned once and then reset to upstream:
    git clone https://github.com/marcoautomation2/AgentsCoordination C:\data\AgentsCoordination
    git -C C:\data\AgentsCoordination remote add upstream https://github.com/MarcoServetto/AgentsCoordination
    git -C C:\data\AgentsCoordination fetch upstream main
    git -C C:\data\AgentsCoordination reset --hard upstream/main
    git -C C:\data\AgentsCoordination clean -x -d --force

  Claude Code reads instructions and skills from %USERPROFILE%\.claude; both
  are links into the checkout, so the reset above resets them too and git
  status in the checkout shows how they have drifted since:
    if (Test-Path $HOME\.claude\skills) { [IO.Directory]::Delete("$HOME\.claude\skills", $true) }
    New-Item -ItemType Junction -Path $HOME\.claude\skills -Target C:\data\AgentsCoordination\skills | Out-Null
    New-Item -ItemType SymbolicLink -Path $HOME\.claude\CLAUDE.md -Target C:\data\AgentsCoordination\CLAUDE.md -Force | Out-Null
  (Directory.Delete removes a junction without touching its target;
  Remove-Item -Recurse would follow it into the checkout.)

  $HOME\.claude\settings.json is a plain file, written back on reset:
    {
      "env": { "EDITOR": "notepad" },
      "permissions": { "defaultMode": "bypassPermissions" },
      "model": "sonnet",
      "autoUpdatesChannel": "latest",
      "skipDangerousModePermissionPrompt": true,
      "theme": "light",
      "agentPushNotifEnabled": true,
      "crossSessionInbound": "accept"
    }
  crossSessionInbound is what lets agent-supervisor.ps1 deliver the
  scheduled messages into a running agent.

  Agent folders. C:\data\fearlessBranch1, C:\data\fearlessBranch2 and
  C:\data\fearlessBranch3 each hold the seven repositories, cloned from the
  marcoautomation2 fork (origin) with upstream set to the parent:
    foreach ($r in 'Commons','Frontend','Coordinator','StandardLibrary','EclipsePlugin'){ git clone https://github.com/marcoautomation2/$r; git -C $r remote add upstream https://github.com/FearlessLang/$r }
    foreach ($r in 'ZeroToHero','FearlessTour'){ git clone https://github.com/marcoautomation2/$r; git -C $r remote add upstream https://github.com/MarcoServetto/$r }
  plus Coordinator\test\mainCoordinator\LocalResources.java: a copy of
  LocalResourcesTemplate.java from the same folder with the class renamed to
  LocalResources and
    private static Path prefix= Path.of("C:\\").resolve("data","fearlessBranchN");
  A folder that already exists needs only the align-branches skill, which is
  the reset for the seven repositories.
  C:\data\winCoordinator holds only logs\diagnostic.log, written by
  cleanup-watchdog.ps1.

  Each of the four folders has a CLAUDE.md holding the single line given in
  the "Shared memory and shared CLAUDE.md" section of CLAUDE.md, and
  $HOME\.claude\projects\<slug>\memory\MEMORY.md holds that section's single
  memory line, where <slug> is the folder path with every \ and : replaced
  by - (C--data-fearlessBranch1, C--data-fearlessBranch2,
  C--data-fearlessBranch3, C--data-winCoordinator). Reset writes those
  files back and deletes every other file in the four memory folders.

  Startup. One scheduled task, at logon, no time limit, highest run level,
  runs autoScripts\agent-supervisor.ps1: it starts the four agents and then,
  for the rest of the boot, delivers each line of
  autoScripts\scheduledTasks.txt at its time and runs
  autoScripts\cleanup-watchdog.ps1 hourly. There is no other task:
    Get-ScheduledTask | Where-Object { $_.TaskName -like 'Claude*' -and $_.TaskName -ne 'ClaudeAgentSupervisor' } | Unregister-ScheduledTask -Confirm:$false
    Register-ScheduledTask -TaskName ClaudeAgentSupervisor -Force `
      -Action (New-ScheduledTaskAction -Execute powershell.exe -Argument '-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File C:\data\AgentsCoordination\autoScripts\agent-supervisor.ps1') `
      -Trigger (New-ScheduledTaskTrigger -AtLogOn -User sonta) `
      -Principal (New-ScheduledTaskPrincipal -UserId sonta -LogonType Interactive -RunLevel Highest) `
      -Settings (New-ScheduledTaskSettingsSet -ExecutionTimeLimit (New-TimeSpan) -MultipleInstances IgnoreNew -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries)

  Reboot (Restart-Computer -Force). Within a few minutes four claude.exe
  processes run, one per agent folder, and Get-ScheduledTask
  ClaudeAgentSupervisor reports Running.

Drift:
  Between resets the machine deviates from this file on purpose; the user
  reviews the deviations, case by case, and decides what is kept, what is
  reverted and what is added here through a PR. What shows them:
    git -C C:\data\AgentsCoordination status      (instructions, skills, scripts; git diff for the content)
    Get-ChildItem C:\data                          (folders and files not named here)
    Get-ChildItem $HOME\.claude\projects\*\memory  (memories beyond the single line)
    Get-ScheduledTask | Where-Object { $_.TaskName -like 'Claude*' }
    Get-Content $HOME\.claude\settings.json
