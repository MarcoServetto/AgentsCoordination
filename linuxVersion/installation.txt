How an agent running on this machine resets it to the state the
linuxVersion/ folder of this repository describes.

Preconditions:
/data/accounts.txt is present.
Display: one 1920x1080 screen at scale 1.0, GNOME on Wayland (~/.config/monitors.xml keeps the mode).
GDM logs agentubuntu in at boot (AutomaticLogin in /etc/gdm3/custom.conf);
screen blanking (gsettings org.gnome.desktop.session idle-delay 0), locking and suspend are off;
notification banners are off (gsettings org.gnome.desktop.notifications show-banners false): when GNOME refuses a window's request to come to the front, it shows a banner "... is ready" over the top of the screen, and that banner takes the clicks meant for the window under it;
agentubuntu has passwordless sudo.
The desk of this machine has a fixed shape, the one the agentTools tests are recorded on; GNOME and the programs of the desk keep what a run changes, so an agent brings the desk back to that shape by hand:
  no window is open;
  no file of Fearless is outside /data/pilotio: no fearless* file in ~/.local/share/applications, ~/.local/share/mime/packages, ~/.local/share/icons/hicolor/*/apps and ~/.local/share/icons/hicolor/*/mimetypes, and no fearless line in ~/.config/mimeapps.list;
  GNOME lists no Fearless program: org.gnome.shell app-picker-layout and the keys under /org/gnome/desktop/notifications/ hold their defaults, except show-banners;
  Files (nautilus) has its default settings and no setting for a single folder;
  org.gnome.shell enabled-extensions is ['ubuntu-appindicators@ubuntu.com'], org.gnome.shell favorite-apps is ['firefox_firefox.desktop', 'org.gnome.Nautilus.desktop', 'snap-store_snap-store.desktop', 'org.gnome.Yelp.desktop', 'org.gnome.Ptyxis.desktop'], org.gnome.mutter center-new-windows is true, and idle-delay and show-banners are as above.
  The commands bringing the desk back to that shape, with no window open:
    pkill -x gvfsd-metadata; rm -rf ~/.local/share/gvfs-metadata
    rm -f ~/.local/share/applications/fearless* ~/.local/share/mime/packages/fearless* ~/.local/share/icons/hicolor/*/apps/fearless* ~/.local/share/icons/hicolor/*/mimetypes/fearless*
    sed -i '/fearless/d' ~/.config/mimeapps.list
    update-mime-database ~/.local/share/mime; update-desktop-database ~/.local/share/applications
    dconf reset -f /org/gnome/nautilus/; dconf reset /org/gnome/shell/app-picker-layout; dconf reset -f /org/gnome/desktop/notifications/
    gsettings set org.gnome.desktop.notifications show-banners false
    gsettings set org.gnome.shell enabled-extensions "['ubuntu-appindicators@ubuntu.com']"
    gsettings set org.gnome.shell favorite-apps "['firefox_firefox.desktop', 'org.gnome.Nautilus.desktop', 'snap-store_snap-store.desktop', 'org.gnome.Yelp.desktop', 'org.gnome.Ptyxis.desktop']"
    gsettings set org.gnome.mutter center-new-windows true
The 12 VMs are defined in /etc/libvirt/qemu.
Each VM <vm> has a clean disk /data/vms/disks/<vm>.qcow2 and runs on its run disk /data/vms/runs/<vm>.qcow2, the disk of its definition: a qcow2 layer over the clean disk, holding only what changes while the VM runs.
A change to the setup of a VM <vm> is vm.sh open <vm>, the change, vm.sh close <vm> and vm.sh keep <vm>.
The clean disk of each VM holds no file of Fearless outside /data/pilotio; each VM logs its user in by itself, answers qemu-guest-agent and mounts /data/pilotio, and its file manager has a sidebar entry pilotio opening /data/pilotio, as the file manager of this machine has (home/.config/gtk-3.0/bookmarks).
The VMs share /data/pilotio over virtiofs (fstab: pilotio /data/pilotio virtiofs defaults,nofail 0 0), except kubuntu_plasma and opensuse_plasma, which share it over 9p: in their definition the filesystem of /data/pilotio has accessmode passthrough and no virtiofs driver, and their fstab reads pilotio /data/pilotio 9p trans=virtio,version=9p2000.L,msize=262144,cache=loose,nofail 0 0.
virtiofs is built on FUSE, and KDE treats a FUSE mount as slow: Dolphin types the files there by their name only, so a program on the share shows as an unknown file and a double click on it opens "Choose Application" instead of offering to launch it.
qemu runs as agentubuntu, uid 1000 like the user of each VM, so files the VM user writes over 9p belong to agentubuntu.
The 9p mount uses cache=loose: with cache=none a program in the VM gets no inotify event for a file another program of the VM creates on the share, and the manager watches its messages folder with inotify.
fedora_cosmic logs its user in through greetd: the package cosmic-greeter owns /etc/greetd/cosmic-greeter.toml and replaces it at every update, so the autologin lives in files no package owns.
  /etc/greetd/autologin.toml: cosmic-greeter.toml plus
    [initial_session]
    command = "start-cosmic"
    user = "tester"
  /etc/systemd/system/cosmic-greeter.service.d/autologin.conf:
    [Service]
    ExecStart=
    ExecStart=greetd --config /etc/greetd/autologin.toml
The GNOME desks of the VMs (debian_gnome_x11, fedora_gnome) start on the desktop, as this machine does, not in the Overview: the user extension startdesktop@pilotio (~/.local/share/gnome-shell/extensions/startdesktop@pilotio, enabled in org.gnome.shell enabled-extensions) hides the Overview once the shell has started:
  metadata.json: {"uuid": "startdesktop@pilotio", "name": "Start on the desktop", "description": "Hides the Overview that GNOME Shell shows at login.", "shell-version": ["48", "49", "50"]}
  extension.js:
    import * as Main from 'resource:///org/gnome/shell/ui/main.js';
    import {Extension} from 'resource:///org/gnome/shell/extensions/extension.js';
    export default class StartDesktop extends Extension{
      enable(){
        if (!Main.layoutManager._startingUp){ return; }
        this._id= Main.layoutManager.connect('startup-complete',()=>Main.overview.hide());
      }
      disable(){
        if (this._id){ Main.layoutManager.disconnect(this._id); this._id= null; }
      }
    }
Their notification banners are off too (show-banners false), as on this machine.
GNOME on this machine takes the Super key before virt-viewer passes it to a VM, so the keys of the tiling desks of the VMs are Alt chords, and in arch_sway and omarchy_hyprland Caps Lock is Super, a key GNOME on this machine passes to virt-viewer:
  arch_sway: wmenu installed; ~/.config/sway/config ends with bindsym Mod1+Return exec foot, bindsym Ctrl+Mod1+t exec foot, bindsym Mod1+Shift+q kill, bindsym Mod1+d exec $menu, input type:keyboard xkb_options caps:super.
  void_i3: dmenu installed; ~/.config/i3/config binds Mod1+d to dmenu_run and Mod1+Shift+q to kill.
  omarchy_hyprland: ~/.config/hypr/bindings.lua ends with o.bind("ALT + RETURN", "Terminal", "foot"), o.bind("CTRL + ALT + T", "Terminal", "foot"), o.bind("ALT + SHIFT + Q", "Close window", hl.dsp.window.close()), o.bind("ALT + SPACE", "Apps menu", "omarchy-menu toggle apps"); ~/.config/hypr/input.lua ends with hl.config({ input = { kb_options = "shift:both_capslock_cancel,caps:super" } }).
The omarchy_hyprland bar keeps tray icons in a drawer that opens only while the pointer is over it; the icon of the Fearless manager is pinned to the bar instead: in ~/.config/omarchy/shell.json the bar entry {"id": "omarchy.tray"} has "pinned": ["fearless-manager"], the Id of the manager's StatusNotifierItem.
omarchy_hyprland draws every window opaque and with no animation, so a window looks the same focused or not and is in its final place as soon as it shows: ~/.config/hypr/hyprland.lua ends with o.window(".*", { opacity = "1 1" }) and hl.config({ animations = { enabled = false } }).
A VM showing its desktop with no input changes its screen at most once a minute (its clock shows no seconds).
java.awt.Robot reaches the screen through the RemoteDesktop portal: ~/.java/robot/remote-desktop-tokens.properties holds only working restore tokens (the first Robot program shows the portal dialog "Remote Desktop", answered with "Allow Remote Interaction" on and Share).
GDM logs in automatically only at boot, so a session that ends leaves the machine
at the greeter, out of reach: the systemd timer session-guard.timer (enabled) reboots
when agentubuntu has no graphical session.
/etc/systemd/system/session-guard.service:
  [Unit]
  Description=Reboot when agentubuntu has no graphical session, so GDM logs it in again
  [Service]
  Type=oneshot
  ExecStart=/bin/sh -c '[ -n "$(loginctl show-user agentubuntu -p Display --value)" ] || systemctl reboot'
/etc/systemd/system/session-guard.timer:
  [Unit]
  Description=Check every minute that agentubuntu has a graphical session
  [Timer]
  OnBootSec=5min
  OnUnitActiveSec=1min
  AccuracySec=10s
  [Install]
  WantedBy=timers.target
The machine is on WiFi (Intel AX211, iwlwifi); its firmware crashes under load
with power saving on, so it is off: /etc/NetworkManager/conf.d/wifi-powersave-off.conf
([connection] wifi.powersave = 2), /etc/modprobe.d/iwlwifi-stability.conf
(options iwlwifi power_save=0; options iwlmvm power_scheme=1) and
/etc/sysctl.d/90-tcp-mtu-probing.conf (net.ipv4.tcp_mtu_probing = 1, the uplink is PPPoE with path MTU 1492).
Claude Code is installed at ~/.local/bin/claude and logged in to claude.ai.
The user reaches the desktop remotely (for example to log Claude Code in again)
over RDP through Tailscale: the machine is behind NAT, so Tailscale is the only way in.
Tailscale: package tailscale from the pkgs.tailscale.com apt repository for this
Ubuntu release, tailscaled enabled, logged in once to the user's tailnet as
linux-agents (sudo tailscale set --operator=agentubuntu; sudo tailscale up --hostname=linux-agents,
the printed URL goes to the user), key expiry disabled in the Tailscale admin console.
GNOME Remote Desktop shares the autologin session: a self-signed TLS key and
certificate in ~/.local/share/gnome-remote-desktop (grdctl rdp set-tls-key, set-tls-cert),
grdctl rdp set-credentials with the Remote desktop user and password of /data/accounts.txt,
grdctl rdp disable-view-only, grdctl rdp enable,
systemctl --user enable --now gnome-remote-desktop.service.
The login keyring has no password (~/.local/share/keyrings/login.keyring is the
plain text form: [keyring] display-name=login lock-on-idle=false lock-after=false;
~/.local/share/keyrings/default contains login): autologin never unlocks an
encrypted keyring, and a locked one puts an unlock prompt on a screen nobody watches.
